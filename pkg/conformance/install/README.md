# CP-0010 · Independent install conformance

These cases were authored from the named specifications and the CP-0010 contract at `18bc39f`. They use small synthetic repositories and no installer implementation. See [independent ownership](../INDEPENDENT.md) and the [open proposals](../../../tenet/packets/CP-0010-tenet-init/escalations/proposals-r5.md).

Each case contains actual files under `before/` and a sequence in `args.json`. Copy `before/` byte-for-byte to a new temporary directory. The empty case's `before/.gitkeep` is fixture metadata and must be excluded from the copied tree. Do not copy test controls into the repository. The Windows case declares an isolated local profile. The path-rejection cases use disposable sibling files only. Compare those sentinels byte-for-byte before and after the command.

Apply case environment overrides to `environment.json` before running any step. Merge object fields recursively and replace scalar or array values. Those settings are test harness inputs for tool discovery, Git state, clock, version and registry integrity. The registry is a stub and its values are fixture data. A Git seed is one initial commit for `committed`, an empty initialized Git repository for `unborn`, and no Git metadata for `not-a-repository` or `tool-unavailable`. Keep Git and local profile metadata outside tree comparisons. Configure scratch Git repositories to preserve fixture bytes, including the CRLF sample, and keep global Git configuration untouched. Keep all runtime actions inside the disposable sandbox.

Each `run` array is a Tenet argv vector. `assertExitCode` checks a specified exit even when the exact finding is undecided. `beforeRun.write` is a compact way to perform a user's exact file edit before a step. `answers` supplies prompt choices. `compareTreeToStep` and `compareTreeToCleanRun` are byte comparisons of changed trees under identical fixture inputs. `interrupt` uses an injected filesystem fault after the named write checkpoint and repeats from a fresh fixture for each checkpoint. `freshLocalCloneOfStep` commits the captured tree, clones it locally, then runs the next command there. None of these controls are Tenet flags.

`expected/NN-command/tree/` is a complete working-tree snapshot where exact bytes are specified. `expected/NN-command/result.json` is an exit-and-finding assertion when both are known. Compare the exit code and presence of the named code in the result. A missing file means the exact result or tree needs the named decision. Assertions for specified final trees and error codes are present even when another step's outputs are open. These fixture files are identified by their READMEs and should not be updated by the future builder.
