# `pkg/conformance/card` — independent conformance cases for `CP-0051` (`tenet test-run` / `tenet record` / proof card)

Written independently from `contracts §5` (`tenet/specs/tech-spec/contracts.md:83–84`), `CI §1–§4` and `§10` (`tenet/specs/tech-spec/ci.md:9–101`, `253–270`), `ALG-07` (`tenet/specs/tech-spec/algorithms.md:104–133`, with every rule capped at `advise` in alpha.0), `ALG-14` (`tenet/specs/tech-spec/algorithms.md:200–208`), `kit/schemas/proof-card.json`, the `CP-0051` build contract (`tenet/specs/plan/alpha.0b.md:65–85`), and the round 4 specification answers (`tenet/packets/CP-0051-proof-job-card-and-records-ref/escalations/answers-r4.md`).

## Running a case

Each case folder holds `input.json`, an exact `expected.json`, and an exact byte-for-byte `expected.md` (no `$assert` projection markers or `"fragments"` mode remain):

- `input.json` provides the `record(event)` input: `event` (including the 7 `evaluation_id` fields from `contracts §5`, `pr_body`, and `records_push`), `bundles` (check bundles produced by `runChecks`), and `repo` (`baseFiles` and `headFiles`).
- `expected.json` holds the complete `{ok, conclusion, wrote, card}` object, with `card` validating against `kit/schemas/proof-card.json`.
- `expected.md` holds the complete LF-terminated Markdown string produced by `renderCard(expected.card)`.

Every outcome row in `CI §10` (`tenet/specs/tech-spec/ci.md:254–269`) that alpha.0 can produce (where every rule is `advise`) is covered below.
