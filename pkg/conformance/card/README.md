# `pkg/conformance/card` — independent conformance cases for `CP-0051` (`tenet test-run` / `tenet record` / proof card)

Written independently from `contracts §5` (`tenet/specs/tech-spec/contracts.md:83–84`), `CI §1–§4` and `§10` (`tenet/specs/tech-spec/ci.md:9–101`, `253–269`), `ALG-07` (`tenet/specs/tech-spec/algorithms.md:148–150`, with every rule capped at `advise` in alpha.0), `ALG-14` (`tenet/specs/tech-spec/evidence.md:39–43`), `kit/schemas/proof-card.json`, and the `CP-0051` build contract (`tenet/specs/plan/alpha.0b.md:65–85`).

## Running a case

Each case folder holds `input.json`, `expected.json`, and `expected.md`:

- `input.json` provides the `record(event)` input: `event` (including the 7 `evaluation_id` fields from `contracts §5`, `pr_body`, and `records_push`), `bundles` (check bundles produced by `runChecks`), and `repo` (`baseFiles` and `headFiles`).
- `expected.json` projects the required fields of `{ok, conclusion, wrote, card}`. As in the other independent conformance suites (`check`, `alg-10`, `board`, `alg-11`), `{"$assert": "present"}` requires a non-empty value, `{"$assert": "contains", "value": [...]}` requires every projected entry to appear in the actual array, and `{"$assert": "size", "value": n}` requires the array length to equal `n`.
- `expected.md` holds the required rendered card lines (`markdownMode: "fragments"` checks that each non-empty line in `expected.md` appears in the rendered Markdown card in order). Complete byte-for-byte Markdown comparisons wait on the renderer questions recorded in `tenet/packets/CP-0051-proof-job-card-and-records-ref/escalations/proposals-r4.md`.

Every outcome row in `CI §10` (`tenet/specs/tech-spec/ci.md:254–269`) that alpha.0 can produce (where every rule is `advise`) is covered below.
