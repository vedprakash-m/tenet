**Context card.** How a project gets Tenet, how its specifications are drafted and blessed, and how Tenet is upgraded and removed. Implements PRD R-223 and tooling R-020, R-021, R-025, R-051 and R-221; the experience is UX spec Parts 0, 1 and 4. File formats: [contracts.md](contracts.md) §1–§4 and §10; algorithms ALG-02, ALG-03, ALG-04, ALG-11, ALG-12, ALG-13.

## 1. Onboarding and blessing (R-223)

<!-- provisional --> **Preflight and inventory.** `tenet onboard` lists what it will read (code, configuration, tests, docs, CI, owners), what it skips (`.env*`, credentials, vendored and generated paths, anything in `onboard.exclude`) and that drafting sends content to the user's own agent and its model provider; `--inventory-only` stops there. It writes `.tenet/onboard/inventory.json` (git-ignored): languages and modules, entry points, routes, commands and schemas it can parse, configuration and flags, tests with names and last results, docs and ADRs with their last-changed dates, CODEOWNERS areas, CI workflows, and the revision it read. A **drafting assignment** (`.tenet/onboard/assignment.json`) points the user's agent to the inventory, the `draft-specs` skill and the layout from the size rule (ALG-11); the agent records the Owner's answers in `interview.json`.

**Draft format.** Requirement lines, citations, conflicts, open questions and front matter follow contracts §3. `inferred` statements cannot be blessed until a person edits or explicitly adopts them (origin becomes `asked`, with `adopted_by`).

**The onboarding card.** The target branch has no Tenet workflow yet, so `tenet onboard` renders the card (what was read, conflicts, sections with reading times, citation check) into the pull request description the agent opens; CI cards begin after the setup merges. Supported starts: protected main (the onboarding pull request), an empty repository (commit to main), a template clone, and a contributor without settings rights (the pull request waits for someone who has them).

**Checks and blessing.** `tenet check` resolves every citation (ALG-04) and flags statements without an origin. `tenet bless` follows ALG-03: interactive only; conflicts first, then each section with its reading time (bless, edit, reject, defer); the person picks who they are from `owners[]`, and the blessing is recorded as `self` (advisory: anyone with write access could edit front matter). From alpha.1 a review action on the pull request also blesses, recorded as `forge`; from alpha.2, `signed`. The **last blessed text stays in force** (the blessed copy); a later text edit is flagged `edited` and is an unblessed proposal; a change to cited code is flagged `sources-changed` and requests review. Re-running `onboard` keeps IDs, edits, rejections and blessings, and proposes only changes.

## 2. Install and upgrade

`init` runs the preflight (R-020), writes `tenet.yaml` (checks with reporter flags per contracts §6; `package.json` is never edited), `tenet.lock`, the `AGENTS.md` block, the proof-job workflow and the detected hosts' skills and MCP entries (contracts §10), records them in `.tenet/manifest.json` and offers onboarding (§1). Existing files are edited only inside marked blocks or owned JSON keys (ALG-12). Integrity is checked by hash; files are not made read-only. `tenet remove` reverses the manifest (ALG-12), keeps specifications and records, and reminds the user to remove the branch rule if the Tenet status was made required. **Upgrade** (0.1.0): update the lock, regenerate the `AGENTS.md` block and skills, report what changed, run `tenet check`; never change the level or start a new rule beyond `observe`. From M4: stage, migrate with a restricted file API, regenerate, swap atomically; classify from structured fields; a scheduled pull request.
