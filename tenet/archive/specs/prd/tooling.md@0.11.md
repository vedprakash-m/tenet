# Tenet requirements: work, views, kit, agents and conformance

> Level L1 · Version 0.11 · Part of [prd.md](../prd.md) · Status: **draft, awaiting the Owner's approval** · Budget: 7,000 tokens · Split from `prd.md` §4.3–§4.4 under the rollover rule (L-0014, L-0016) · Previous version: `archive/specs/prd/tooling.md@0.10.md`

**Context card.** Requirements for work items and views, how the standard is written and versioned, how the kit is installed and kept current, how agents and engines bind to it, and how conformance is tested. Columns and guarantee levels follow [prd.md §4](../prd.md#4-requirements). The spec process (§4.0), the kernel (§4.1) and trust (§4.2) stay in `prd.md`; adoption and friction are §3 here, trust and verification §4.

## 3. Adoption and friction

| ID | Requirement | Serves | Release | Guarantee | Status |
|---|---|---|---|---|---|
| R-214 | **One adoption setting.** `level` is `observe` (default: nothing blocks, self-acceptance allowed and labelled, no keys, bots or CI setup beyond one workflow), `protect` (rules the Owner turned on block; native reviews), `verify` (signed evidence, merging requires its status, forge decisions count) or `assure` (person-present decisions, external holdout, strict separation of duties, vision ratified twice). | R-216 | **Friction budget.** Tenet records refusals, overrides, waivers and "not useful" marks per rule and the human minutes Tenet takes (V-M11); a rule above its budget (default: over 10% not useful, or over 2 false blocks per 100 changes) is flagged for demotion at the release retrospective | V-B10, V-P7 | 0.1.0 | — | proposed |
| R-217 | **Safe failure.** When a control cannot run (CI unavailable, keys missing, review unobservable, check timed out), the result says so. At `observe` and `protect` it is advisory and nothing blocks. At `verify` and `assure` it fails closed for every change; an override is a waiver recorded as `accepted-without-verification`, never `verified`. Nothing silently passes | V-B8, V-P12 | 0.1.0 | detected | proposed |
| R-218 | **Proof card.** Every same-repository pull request gets one summary: acceptance items proven, unproven or skipped on the tested commit; tests deleted, skipped or weakened (by the patterns in ALG-09); protected files touched; spec sections affected; what would have been blocked. Each line states its method ("test passed on this commit", "failed as expected on the base", "no weakening detected by these checks"); the acceptance text's digest is bound to the evidence, so editing it re-evaluates. Until 0.1.0-alpha.2 it is built by the **proof job**, which runs the checks named in `tenet.yaml` itself (reporter flags in `checks.<name>.run`; `package.json` is never edited) and keeps unsigned results on the records ref; from alpha.2 the attest job signs it. In 0.1.0-alpha.0 it evaluates three built-in rules (`acceptance-proven`, `tests-not-weakened`, `protected-surfaces`) for "would have blocked". It is a check run named `Tenet`; fork pull requests, whose token is read-only, get the same content as a job summary. Before a baseline is blessed it reads "advisory · intent not yet blessed" | V-V1, V-P2, V-M1 | 0.1.0 | advisory; enforced* at verify | proposed |
| R-219 | **Tenet does the bookkeeping.** IDs, links, status and events are generated; people never type an ID or digest. `tenet fix` repairs mechanical problems in local files (IDs, links, front matter); it never edits a pull request: agents write acceptance IDs when they write the description, and the proof card reports any missing. Hooks warn and CI enforces; every refusal leads with plain words and one sentence on why the rule exists | V-B10, V-V1 | 0.1.0 | — | proposed |
| R-222 | **Host capability levels.** Each agent host is described by what it can do with Tenet: passive (its pull requests get proof cards), instructions (`AGENTS.md`), skills, MCP, or enforced (a host binding restricts protected writes); `init` shows the level it detected and lists every host file it writes | V-P12, V-B8 | 0.1.0 | — | proposed |

## 4. Trust and verification

| ID | Requirement | Serves | Release | Guarantee | Status |
|---|---|---|---|---|---|
| R-100 | **Two-job verifier** (from `verify`; below it a plain proof job produces advisory receipts): a check job runs pinned checks with no credentials, no write access, network denied by default, an environment-variable allowlist, no cache shared with the attest job and a recorded runner image; it detects checks that edit tracked files, passes only on exit code 0 with a valid report, and writes its bundle outside the working tree; an attest job never runs the change, parses the bundle as data, checks protected claims, replays events and **signs each evidence record with an identity only the protected job holds** (method chosen by CP-0040: a public signing service for public repositories, or a key held by the protected job), so a record cannot be forged or altered wherever it is stored (it does not by itself prove the check was right); a store only that job can write is the fallback. Tenet ships one hardened reference workflow | V-P2, V-B7 | 0.1.0 | enforced* | proposed |
| R-110 | The attest job observes the trust properties: **T1** the verifier runs from a protected source; **T2** evidence carries a signature only that job can make; **T3** decisions reserved to people carry proof an agent cannot produce; **T4** agents never hold decision-makers' credentials (declared in the policy and spot-checked: agent commits from declared bot identities, no decision from the account whose agent session opened the pull request; it supports enforced* only where a host binding attests it). Separately it observes whether merging requires the Tenet status (`unavailable` on forge plans without merge protection). `enforced*` counts as enforced only while a fresh observation holds | V-P12, V-B8 | 0.1.0 | — | proposed |
| R-104 | `holdout.mode` is `external` (outside the build repository) or `in-repo` (always advisory) | V-P11, V-P12 | 0.1.0 (declared); M2 | advisory; enforced* if external | proposed |
| R-105 | A run with both untrusted input and sensitive data gets no network and may change only its worktree; assignment inputs carry source, trust and hash, and the evaluator refuses an assignment that combines all three properties | V-P11, V-B5 | 0.1.0 | advisory (declared); as the host enforces | proposed |
