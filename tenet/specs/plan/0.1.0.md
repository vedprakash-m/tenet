# Tenet plan: 0.1.0

> Level L2 · Track 1 draft for Owner approval · Budget: 6,000 tokens · Part of [plan.md](../plan.md)

**Context card.** CP-0022 → CP-0020 → CP-0055 → CP-0013 → CP-0024. CP-0056 ran in M0 and L-0030 selects the adapters. CP-0014 stays on the evidence track. Uses [kernel](../tech-spec/kernel.md) (K), [contracts](../tech-spec/contracts.md) (C), [CI](../tech-spec/ci.md), [agents](../tech-spec/agents.md) (AG) and the [technical specification](../tech-spec.md) (TS). Standard JSON envelopes, exit codes, and three-platform checks follow the alpha.0 build contracts.

**CP-0022 · Reference agent cards · R-012, R-013, R-015**
1. *Needs:* Alpha.2; CP-0004 card schema; CP-0049 criteria schema; AG §§4–5.
2. *Owns:* `kit/agents/{shaper,test-writer,builder,judge}.md`, two skills from AG §4, `kit/criteria/`, `agent check`, `test/agents/`, private activation suites.
3. *Exports:* Four cards, two skills, criteria and `tenet agent check [<card>] [--json] → {cards, valid}`.
4. *Behavior:* Give the shaper intake and context. The test writer sees only the approved definition and public interfaces. The builder gets verified pins. The read-only judge receives results and the advisory card. Check references and permissions before dispatch. Five-case activation gives advisory status only.
5. *Edge cases:* Unknown card, widened tool scope, shared test-writer and builder definition, changed digest and out-of-scope review.
6. *Out of scope:* Running hosts, forge operations and qualification beyond activation.
7. *Fixtures:* `test/agents/{cards,unknown-skill,widened-tools,same-definition,wrong-role}.json` and private activation inputs and answer keys.
8. *Proving:* `npm test -- test/agents`, then `tenet agent check --json`. Retain five case outcomes per activation suite.

**CP-0020 · Host binding and work commands · R-014, R-036, R-040, R-042, R-044, R-046, R-047, R-105, R-107, R-111, R-124, R-156**
1. *Needs:* CP-0022; CP-0049; CP-0050; TS §§3–6, 11; C §8; AG §5.
2. *Owns:* Work command modules, `src/work/`, `src/bindings/agents-md.ts`, local advisory check entry point, `kit/loops/{define,build,verify,fix}.yaml`, `test/work/`.
3. *Exports:* `new`, `move`, `status`, `task done`, `close` subject to the release reconciliation, `resume`, `decide`, `resolve`, `escalate`, `lease`, `release`, `assign`, `result`, `inspect`, `record`, `skill list`, `build --target agents-md` and `verify --run-checks --local`. Mutations return work, events and next action.
4. *Behavior:* Validate work and authority before event append. Apply AG §5 routing and explicit repair targets. `new` prepares the work and branch. `resume` reconciles accepted effects. `record --pin-tests` returns the pin digest. `result` validates attempt and hashes. `status` and `inspect` are read-only. Escalation records a decision request. Local checks produce an advisory card.
5. *Edge cases:* Repeated task completion, stale input, expired lease, omitted context, stale pin, advisory refusal and late evidence.
6. *Out of scope:* Host processes, forge writes, global leases and permission enforcement beyond the chosen host.
7. *Fixtures:* `test/work/{quick,careful,expired-lease,duplicate-result,declined-definition,stale-pin,disposition-routing,fix-target,stop-threshold}/`.
8. *Proving:* `npm test -- test/work`. Confirm one approval, writer pins precede the build, all routes match AG §5, and the third consecutive failure opens one escalation.

**CP-0055 · Reference runner · R-041, R-043, R-224**
1. *Needs:* CP-0020; CP-0056 results in L-0030; AG §§5–6; C §8.
2. *Owns:* `runner/`, adapters `claude-code`, `copilot-cli`, `command`, and `test/runner/`.
3. *Exports:* `tenet-runner start <work> [--adapter <name>] [--until approval|pull-request|done] [--parallel <n>]`, `status <work>`, `stop <work>`, `doctor`, and AG §6 adapter interface.
4. *Behavior:* Use AG §6 attempt checkpoints. Reconcile before dispatch and publish only accepted output. Establish a draft and accepted definition before the human decision. Push the tested candidate before waiting for its CI card. Preserve user work on cancellation and publish the runner at the matching core version.
5. *Edge cases:* Lost acknowledgements, lease takeover, dirty worktree, no result, timeout, unsupported capability and insufficient adapter proving.
6. *Out of scope:* Model calls by the runner, evidence signing, cross-clone exclusivity and host guarantees not established by testing.
7. *Fixtures:* `test/runner/{scripted-host,attempt-recovery,late-result,push-receipt,draft-receipt,approval,stop-tree,host-output,adapter-fallback}/`.
8. *Proving:* `npm test -- test/runner` with a fake host on three platforms. Prove the careful lane and matching CI card with both named adapters or one named adapter plus the command adapter in a real sandbox. Interrupt after each checkpoint and assert one logical effect. Stop leaves no owned live descendant and preserves uncommitted work.

**CP-0013 · Quick start and first contact · R-221**
1. *Needs:* CP-0055; UX Parts 0–1; README; CI release procedure.
2. *Owns:* README first screen, starter repository payload, `docs/quick-start/`, quick-start CI, `scripts/quick-start`, the `prove:quick-start` script entry and fixtures.
3. *Exports:* Two candidate-install journeys, starter files and prompt.
4. *Behavior:* Start with the packed candidate and temporary repositories. Execute existing and new setup through a merged change, a governed spec change, a careful change and board. Identify required host, forge and executables.
5. *Edge cases:* No settings rights, failed global install, existing CI, version mismatch and prepublication candidate resolution.
6. *Out of scope:* Capability implementation, Torus dogfood and independent adopter sign-off.
7. *Fixtures:* `test/quick-start/{existing,new,without-settings,existing-ci}/` with expected card outcomes.
8. *Proving:* `npm run prove:quick-start -- --candidate <tgz>`. Run both documented journeys on all three platforms and the shipped prompt with qualifying hosts.

**CP-0024 · Release 0.1.0 · R-004, R-005, R-221**
1. *Needs:* CP-0013; CI release procedure; plan §1 build gate. CP-0014 is independent evidence.
2. *Owns:* Changelog, `kit.json`, release package manifest checks, both release tarballs, digests, starter pins, release decision and release record.
3. *Exports:* Matching core and runner packages, kit archive and public release provenance.
4. *Behavior:* Pack once and prove the same pair across all platforms. Pin the exact matching core. Verify both registry digests before promotion and starter update. Reconcile partial publication by version and digest. Require the applicable licence materials in each packed artifact and verify the stable schema IDs resolve from the published schema site after release, per L-0031. Keep evidence and announcement separate from the build gate.
5. *Edge cases:* Package pair mismatch, partial publish, unavailable provenance, unexpected registry digest and stale starter.
6. *Out of scope:* Pilot completion, changed release criteria and new licensing decisions.
7. *Fixtures:* `test/release/{matching-pair,version-mismatch,partial-publication,wrong-digest,starter-candidate}/`.
8. *Proving:* `npm run prove:quick-start -- --candidate <tenet-tgz> --runner <runner-tgz>` and `npm test -- test/release`. Run real sandbox careful-lane proving. Verify published digests and starter pins match the tested pair. Record pending announcement evidence.

**CP-0014 · Dogfood on Torus · V-H1, V-M8 · Evidence track**
1. *Needs:* CP-0055.
2. *Owns:* Torus adoption and the three-change sequence with time per station.
8. *Proving:* Five verified changes, two careful. Stop if setup exceeds one day or more than two record edits are manual. This evidence does not block the CP-0024 build.
