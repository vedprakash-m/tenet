## 2. Findings

1. **should** · `src/verify/record.ts:212` versus `tenet/specs/tech-spec/contracts.md:84` and `tenet/packets/CP-0051-proof-job-card-and-records-ref/escalations/answers-r4.md:40`. When `specifications()` builds `blessings_changed` from git history (rather than an injected `deps.specification`), `src/verify/record.ts:212` sets `doc: filename` (the repository-relative file path, such as `"tenet/intent.md"`), whereas `contracts.md:38` and `answers-r4.md` (`p04-blessings-changed-and-requirement-deltas`) use the specification's document identifier (`tenet.doc ?? filename`, e.g. `"intent"`, rendering `Blessings changed: intent#requirements …`). **Fix:** set `doc: typeof fields(doc.front?.tenet).doc === "string" ? String(fields(doc.front?.tenet).doc) : filename` at `src/verify/record.ts:212`.
2. **should** · `src/verify/record.ts:441` versus `tenet/specs/tech-spec/evidence.md:54` (`ALG-08`). `record.ts:441` computes per-requirement test counts on the card via `itemResults([{ id }], reports, { acceptance: declared.requirement })`. Under `evidence.md:54` ("`AB-n` counts when its source line or enclosing `describe(`-inherited inner declaration line is added in `git diff -U0 <base>..<tested>`; requirement tags count anywhere") and `src/reports/declared.ts:22–36`, `declared.requirement` contains declarations tagged with the requirement ID (`[C-1]` / `tenet_C_1`), not declarations tagged only with `[AB-1]`. However, `declaredTags(tested.base, tested.commit, …)` only scans test files present in `headScan` and matches `itemResults` by declaration title, whereas a test that only carries `[AB-1]` (without `[C-1]`) leaves `declared.requirement["C-1"]` empty (`tests: {expected: 0, passed: 0, …}`). The specification needs to state explicitly whether `requirements[].tests` counts only requirement-tagged declarations (`[C-1]`) or also acceptance-tagged declarations for an `Implements: C-1` change (settled in `answers-r6.md` Q2). **Fix:** align `requirements[].tests` attribution and the `pkg/conformance/card/` fixtures with `answers-r6.md` Q2.
3. **should** · `src/verify/card.ts:92` and `src/verify/record.ts:331–332` versus `tenet/specs/tech-spec/ci.md:151, 237` (`CI §3` and `§8`). When the essential (non-trimmable) lines of a proof card exceed the 60,000-character forge check-run summary limit, `renderCheckSummary` throws `RangeError("required proof details exceed the check summary limit")`, causing `publish()` to abort before posting any check run or writing `refs/tenet/records` (logged in `pending-r6.md` Q4). **Fix:** per `answers-r6.md` Q4, when `essential.length > limit`, write the full proof card to `refs/tenet/records` first, truncate the check-run summary at `limit` with a trailing pointer line `… (truncated at 60,000 characters · full proof card in refs/tenet/records proof/<work>/<evaluation_id>)`, add `"check summary exceeded 60,000 characters; full proof card in refs/tenet/records"` to `degraded`, and post conclusion `"neutral"` (`"failure"` at `verify`/`assure`).
4. **nit** · `src/verify/record.ts:194` versus `tenet/specs/tech-spec/algorithms.md:51` (`ALG-03`). `specifications()` compares `digest(bytes.toString("utf8")) !== section.blessed_digest` directly; depending on whether `CP-0044`'s `sectionDigest` returns a bare 64-hex digest or a `"sha256:<hex>"`-prefixed string, one of the two representations would not match unless normalized. **Fix:** normalize any leading `"sha256:"` prefix on both sides before comparing in `src/verify/record.ts:194`.
