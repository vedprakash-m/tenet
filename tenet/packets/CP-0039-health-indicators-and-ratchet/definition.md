# CP-0039 definition · Health indicators and ratchet

> Shape round 2 · Implements `R-175`–`R-178` · Sources: [research-code-health.md](evidence/research-code-health.md), [review-r1-gpt.md](escalations/review-r1-gpt.md), [L-0038](../../ledger/L-0038-review-rounds-and-public-home.md), [plan/0.1.x.md](../../specs/plan/0.1.x.md).

## 1. Problem and outcome

Code health means software stays changeable (`V-V10`, `V-P9`) and earlier promises hold without turning legacy debt into a blocker (`V-M10`). Whole-repo thresholds stall delivery, offline bug lists yield low action compared to diff-time comments (Meta observed ~0% fix rate on offline lists vs ~70% on review comments), noisy checks trigger workarounds, and benchmark stress tests show agents gaming checks they can edit (30.4% in METR RE-Bench; 49%–76% in ImpossibleBench), motivating protected inputs and evidence rather than predicting Tenet's own rates.

**Goodness without the tax:** record existing debt as a protected baseline, gate only regressions on touched scope beyond tolerance, tighten monotonically from `main`, post actionable summaries on the proof card, verify check provenance and surface diffs against tampering, and track check noise (`R-177`/`R-216`) without blocking fast work.

## 3. Design

### 3.1 Authoritative baseline, precedence & `main` tightening (F1)
- **Two stores, one deterministic rule (reconciling `protect` with automatic tightening):**
  1. Committed `.tenet/health-baseline.json` (`protect` surface; changes require `change-policy`): holds initial adoption (`origin: observed`), manual `config_digest` resets (`reset_seq`), or deliberate re-baselining.
  2. Protected `refs/tenet/records: health/baseline.json` (signed on `refs/tenet/evidence` at `verify`/`assure`, matching `ci.md §4–§5`): written **only** by the recorder / attest job on default-branch (`main`) push runs via git plumbing CAS + jitter retry. Recorder never edits committed `.tenet/health-baseline.json` on branch tips.
- **Precedence & in-flight stability:** Every evaluation snapshot pins one `baseline_digest` and target `base` (`kernel §2`). If committed `.tenet/health-baseline.json` has a higher `reset_seq` or a newer `config_digest` commit than `records`, committed wins (`reset`); otherwise for matching `(tool, tool_version, config_digest)`, the effective baseline per `(area, indicator)` is the **strictly tighter** of committed `.tenet/health-baseline.json` and `records`. An in-flight PR keeps its evaluation's pinned baseline across replay until pushed/re-evaluated.
- **Forward-only ordering & completeness guard:** Recorder tracks `(main_seq, main_commit, run.created_at)`. A `main` push run whose commit is a strict ancestor of `records.main_commit` never updates `health/baseline.json`. An indicator `I` in area `A` tightens on `main` **only when all hold**: `exit_code === 0`, `complete === true` covering all of `A` (never partial subsets or truncated reports), exact match on `(tool, tool_version, config_digest)`, `aggregation !== "sampled_runs"` (sampled metrics never auto-tighten), and no active unfixed `accept-health-regression` exception on `(A, I)` (so a waived regression never widens or erases tracked debt). Incomplete/failed runs leave `finding_set` baselines untouched.
- **Stale baseline & config mismatch:** If `finding_set` shows resolved findings in touched files not yet pruned from a committed floor, emit `"baseline stale"` (`advise`, never blocking cleanup PRs). If `(tool, tool_version, config_digest)` differs between run and baseline, emit `TN-HEALTH-CONFIG-CHANGED` (`re-baseline via change-policy`), never silently passing.

### 3.2 Indicator kinds & exact comparisons (F3, F4, F6)
- **Kinds (`measurement`, `evidence.md §1`):**
  1. **`scalar`:** `{kind: "scalar", population: "area" | "touched" | "sampled_runs", unit, direction: "up" | "down", value, numerator?, denominator?, scope_digest, samples?}`. Unit, direction, and population must match baseline (`TN-HEALTH-INCOMPATIBLE` otherwise); non-finite values fail `TN-REPORT-MALFORMED`.
     - `area` ratios/values compare whole-area `tested` against whole-area `baseline` (eligible for `main` tightening). A PR slice's favorable ratio (`touched` or subset) **never** updates an `area` baseline.
     - `touched` metrics evaluate against a declared ceiling OR paired recomputation (`tested` vs `base` recomputed over the identical touched files/lines), never comparing a `touched` slice against a whole-`area` baseline.
     - `sampled_runs` (suite time, flake rate) report multi-run `samples` + visible `quarantined` count, never auto-tighten, and cap at `advise`.
     - **Tolerance & zero guards:** `tolerance: {kind: "absolute" | "relative-pct", value}` (`value >= 0`; boundary equality `<=`/`>=` passes cleanly after deterministic `1e-6` rounding or exact rational comparison when `numerator`/`denominator` exist). `absolute` uses `scalar.unit`; `relative-pct` at `baseline === 0` allows `0` slack (any `> 0` regression fails `"down"`). `denominator === 0` yields `not-applicable` when zero measurable units exist in scope, else `inconclusive` (`TN-GATE-UNKNOWN`).
  2. **`finding_set`:** `{kind: "finding_set", scope: "touched_lines" | "touched_files" | "area", max_new: integer >= 0, findings: [{fingerprint, rule_id, file, symbol?, line?, hint}]}`.
     - **Shift-proof identity & duplicate handling (F4):** Canonical key `fp_key = sha256(RFC 8785 {rule_id, file: normalized_path, symbol: normalized_symbol, snippet: normalized_snippet_hash})` (CRLF->LF, horizontal whitespace collapsed; `symbol: ""` when absent). Comparisons match **multiset occurrence counts** per `fp_key` in canonical appearance order (`baseline_count` vs `current_count`), so two identical violations inside one symbol cannot collapse into one; `current_count > baseline_count` flags exact excess occurrences `current_count - baseline_count`.
  3. **Architecture rules (`R-176`, F6):** Pinned rule definition digest + canonical findings:
     - Edge violations (`forbidden_import`, `layer_violation`): `{kind: "edge", rule_id, from_module, to_module, from_file, to_file?, hint}`, keyed on `sha256(RFC 8785 {kind: "edge", rule_id, from_module, to_module})`.
     - Cycles: `{kind: "cycle", rule_id, cycle_nodes: [module_id...], cycle_edges?: [{from, to}], hint}`. Normalize `cycle_nodes` to the **minimal rotation starting at the lexicographically smallest module ID** so traversing or reordering the same cycle yields one stable fingerprint, while adding an edge that creates/enlarges a cycle creates a new fingerprint. Missing/partial graph completeness -> `inconclusive` / `unknown` (never green). Non-empty `hint` required (`evidence.md:11`).

### 3.3 Touched scope & attribution (F4, F5, F6)
- **Diff & path protocol (`ALG-15`, shared with `ALG-08/09/14` & `CP-0036`):** Run `git -c core.quotepath=false diff -U0 -M <base_sha>..<tested_sha>` (`tested_sha` = merge candidate if provided, else PR head; `base_sha` = pinned merge-base SHA, never floating branch name). Normalize UTF-8 paths to POSIX forward slashes, preserve quotes/unusual names, and sort bytes lexicographically (`Buffer.compare`).
- **Scope filtering & exemptions (F5 — no blanket 20-line bypass):**
  - Remove the universal `min_changed_lines: 20` exemption from enforced `R-175` checks: a 1-line adverse change on an enforced indicator still counts and blocks (`not-applicable` applies **only** when `denominator === 0`, zero measurable units touched). Ratios may still attach `low_sample: true` (`confidence: "low"`) below `low_sample_under` (default `20` lines) as advisory context only.
  - `touched_files` evaluates multiset counts over all findings in modified/added/renamed files (`A|M|R`), unaffected by shifted line numbers. `-M` renames carry `1:1` baseline credit across `(old_path -> new_path)` so pure renames pass while a rename plus a new violation catches `+1`.
  - `touched_lines` overlaps new-side added/modified hunks **and** matches deletion/edit breaks (e.g. broken doc links when cited `old_path` was deleted/edited in diff).
  - Locationless findings (`file: null`) bind to declared `area`; `R-176` attributes affected areas from `from_file`/`to_module` on new edges and touched edges in new cycles (`algorithms.md §ALG-06` -> `CODEOWNERS`); paths mapping to no area refuse with `TN-GATE-UNKNOWN`.

### 3.4 Provenance, outcomes, tamper & policy precedence (F2, F7)
- **Trusted provenance (`ci.md §2–§5`, F2):** Core accepts canonical `tenet-health-json` (`kit/schemas/health-input.json`); optional adapters (`sarif` 2.1.0, `lcov`/`cobertura` for **area trends only** in `0.1.x`) normalize into it under `ci.md §3` per-file bounds (`50 MB`, depth `64`, `20,000` findings/cases) and per-bundle `20,000`-item cap. Test job records `{tested_commit, base_commit, check_id, run_id, adapter_version, exit_code, complete, analyzed_scope, report_sha256, tool, tool_version, config_digest, pinned_inputs_digest}` from target `base` configs (`inputs[]`, lockfiles). When legacy emitters (`lcov`, `cobertura`) omit tool headers, the trusted runner receipt supplies `{tool, tool_version, config_digest}`. Below `verify` (and while subject code runs inside the check job), this remains a detected integrity boundary (honest limit per `tech-spec.md §14`).
- **Health outcome matrix (aligned with `ci.md §10`):**

| Outcome / Input Condition | `observe` / `protect` | `verify` / `assure` | Tightens `main`? |
|---|---|---|---|
| Valid, `exit_code === 0`, `complete: true`, provenance OK | Evaluate ratchet (`holding`/`improved`/`regressed`) | Evaluate ratchet (blocks if `enforce` & unwaived) | Yes (monotonic, unwaived) |
| Valid empty findings, `complete: true`, `analyzed_scope` covers target | `holding` (`improved` on `main` if tightening) | `holding` | Yes |
| Missing/malformed/truncated report, `complete: false`, 0 scope | `unknown` (advisory `"not checked"`) | `failure` (`unknown`, never silent pass) | Never |
| Wrong subject commit / pinned `inputs_digest` mismatch / missing provenance | `inadmissible` (advisory `"untrusted input"`) | `failure` (`TN-HEALTH-PROVENANCE`) | Never |
| Non-zero `exit_code` (even with passing report) | `failed` | `failure` | Never |

- **Tamper check (`R-103` mapping):** PR diffs touching (1) `.tenet/health-baseline.json`, `tenet.yaml`, workflows, or `protect` `inputs` -> `protected-surfaces` (`change-policy`); (2) tests (`ALG-09`) or added inline suppression tokens (per-language configurable map, e.g. `biome-ignore`, `eslint-disable`, `@ts-expect-error`, `# noqa`, `//nolint`, `#[allow(`) -> `weakening` / `health-tamper`; (3) non-`protect` tool configs (`package.json`, `tsconfig.json`, etc.) -> `mechanics` (`! Tamper watch:` + requires non-author review).
- **Mode precedence & tightening (`F7`, extending `ALG-06`):**
  1. Effective mode = `min(rules["health-ratchet"], indicator.declared_mode, metric_cap)` (`observe < advise < enforce`), where `sampled_runs` has `metric_cap = "advise"` (schema refuses `mode: "enforce"` on `sampled_runs`, and capped metrics grant **zero** credit toward an `enforce` lane claim).
  2. PR adding/promoting an indicator in `tenet.yaml` runs at `observe` below `verify` (`"proposed · approve tenet.yaml to pin"`) and refuses unapproved promotion (`change-policy`, `TN-POLICY-RULE-DECISION`) at `verify`/`assure`.
  3. Cross-layer merge (`pack -> area -> project`): changing `kind`, `unit`, `direction`, `population`, `scope`, `check`, `tolerance.kind`, or removing an inherited indicator is `TN-POLICY-INCOMPATIBLE`; raising `tolerance`/`max_new`, lowering `samples` floor, narrowing `scope_globs` out of parent paths, or weakening `mode` is `TN-POLICY-LOOSEN`.

### 3.5 Waive authority, expiry & durability view (F8, F9)
- **Waive (`accept-health-regression`, F8):** Uses existing Kernel `Decision` (`tech-spec.md:64`, `kernel.md §3`, `ci.md §6`): `kind: "waive"`, `name: "accept-health-regression"`, `subject`, `target` (indicator/claim IDs), `scope` (`area`, `indicators`, `evaluation_id`), non-empty `reason`, and existing `expiry` field (`now >= expiry` is expired per `kernel.md:40`; default `issued_at + 30d`, capped by `waiver_max_days`, required on creation). Proof: `forge-verified` (`ci.md §6:199`; `person-present` at `assure` noted in §8 Q2). Authorized actor = indicator `owner` -> `area` owner -> `owners[]`; **R-203 enforcement:** PR author, diff commit authors, and agents/bots acting for them fail `TN-GATE-SELF-WAIVE` at `verify`/`assure` (labelled `self-waived` below `verify`). Unexpired waiver passes **only that evaluation** (never replayed as blanket permission for new regressions), while historical replay of that closed PR keeps its record; post-merge, the active shortfall tracks against `expiry` on `board` (`R-143`, `V-M10`) so once `now >= expiry` without fix or `change-policy` re-baseline, area health flips to `declined / expired-waiver` cleanly.
- **Durability view (`R-178`, F9):** Mature cohort = integrated default-branch commits `M` in `[as_of - 60d, as_of - 30d]` (integrations `< 30d` old sit separately under `provisional`, never mixed into mature denominators). Track every inserted non-generated source line `L_0` (`+` hunks in `git diff -U0 -M <parent>..<M>`, excluding `tenet/`, `.tenet/`, `linguist-generated`) over `[M.merged_at, M.merged_at + 30d]` along default-branch history with `-M` rename following (pure renames untouched; squash merges use `M`; revert or later line edit/delete marks `L_0` **once**). Join `{agent_definition, work_type}` from immutable run/work events (`CP-0037`; missing/unattributed grouped explicitly as `human`/`mixed`/`unknown` with `missing_attribution_commits` disclosed). Output grouped by `(agent_definition, work_type)`: `{cohort_commits, lines_added, lines_rewritten_or_reverted_30d, durability_rate, missing_attribution_commits, provisional}`.

### 3.6 Rollout, noise counters, proof card & determinism (F10, F12)
- **Check owners & 4 separate counters (`R-177`, `R-216`, F10):** Every pinned `checks.<name>` and `health.indicators.<name>` resolves `owner` (`indicator.owner ?? check.owner ?? area.owner`). Record separate counters (deduplicated per unique `(evaluation_id, finding_id)` across retries; zero quick-lane human inputs): (1) `not_useful` (`/tenet not-useful` / surfaced findings; `0` denominator -> `n/a`; flag when `> 10%`); (2) `waived` (`accept-health-regression`); (3) `overrides`; (4) `false_blocks` (adjudicated wrong refusals per 100 evaluated changes; retrospective demotion flag when `> 2 / 100` per `R-216`, aiming under `V-M11`'s `< 2 / 100`). Flag is advisory for retrospective review, never auto-editing policy.
- **Proof card (`contracts.md §5`, `ci.md:151`, F12):** Summary line `Health: <H> holding · <I> improved · <R> regressed · <W> waived · <U> unknown · <S> n/a` (never hidden when indicators are configured and any is `unknown`!). Sorted sections: `blocking_regressed` (`area, indicator, path`), `tamper_watch`, `stale/config_changed/unknown`, `waived`, `advisory_regressed`, `improved`, collapsed `holding`. Multi-PR shared head respects $\lfloor(60000 - \text{overhead})/N\rfloor$; verbose details trim first; if essential lines overflow 60k chars, write the full card to `refs/tenet/records` (`proof/<pr>/<evaluation_id>/health.md`) and post compact totals + blocking indicator names + record link preserving true CI `conclusion`.
- **Determinism (`contracts.md §11`):** CRLF->LF, `-c core.quotepath=false`, forward slashes, RFC 8785, byte/ASCII explicit sorts, explicit `<base_sha>`, injected clock, shift-proof multiset/cycle IDs.
