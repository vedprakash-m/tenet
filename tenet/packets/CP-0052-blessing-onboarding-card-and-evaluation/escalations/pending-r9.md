# CP-0052 · Round 9 specification questions

1. **Version increments** (ALG-03, algorithms.md:44). The text calls for a version bump when blessed text changes, while the schema accepts any version string. This implementation keeps the initial version at first blessing and increments the final numeric component when a replacement changes the text. Proposal: standardize numeric versions and this increment rule, including the behavior for old nonnumeric values.
2. **Log granularity and unavailable measures** (contracts.md:21, onboarding.md:62,116–124). A log row names one section, while the text says one line per session. This implementation appends one row per finished section with the elapsed session minutes at that point. The five statement counts are null if the pinned draft or section cannot be read. Proposal: define a session ID, a per-section action field, cumulative duration, and the nullable count shape. An adoption that changes only metadata counts as both kept and adopted. Specify these counts for deferred sections and for deleted or reworded prose.
3. **Contradiction review and ownership** (onboarding.md:61,66, algorithms.md:32–35,53). There is no deterministic grammar for deciding whether an option contradicts a statement or maps to multiple statements. The prompt asks the person to identify an affected statement and opens the file for correction before storing the resolution. The selected ID must change text or disappear before the resolution is accepted. Proposal: let a conflict declare affected IDs, require human confirmation of the complete correction, and state whether alpha.0 should limit the chooser to section/CODEOWNERS principals or record any configured owner as self-attributed.
4. **Anchor sidecar and copy naming** (algorithms.md:38–39, contracts.md:47–49). This implementation uses the repository-relative document path with slashes replaced by double underscores, retains the extension, and stores the text returned by the shared anchor helper as a citation-to-text object. Proposal: pin the exact path and sidecar format, including Windows case, underscores versus slash collisions, and normalized versus raw trailing whitespace. If a cited source is missing, confirmation leaves the previous proof in force until the citation resolves.
5. **Card format and branch handoff** (onboarding.md:48,53–61, agents.md:88). The referenced onboarding goldens are absent at the base. This card uses the UX order, a deterministic section row, and the literal PR-number placeholder when called through the CLI before a PR exists. The SDK can supply a known PR number. Proposal: publish goldens for the supported starts, define the exact origin/count and time format, and have the drafter commit the stamped front matter separately before opening the PR. The stamp remains pinned on reruns, including after a squash. A new draft needs an explicit re-baseline operation if a document already carries a stamp.
6. **Interruption and parallel writers** (alpha.0b.md:133, algorithms.md:36–42). A finished section is persisted before the next prompt and recoverable write errors roll back that action's changed files. Proposal: specify an on-disk transaction/lock protocol if process termination during a multi-file write or simultaneous blessing sessions must be supported. Plain EOF and SIGINT use the session interruption path.
