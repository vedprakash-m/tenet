# Answers — CP-0052 round 9

1. **Version numbering (`contracts.md` §3; `algorithms.md` `ALG-03`)**
   Managed `tenet.version` values use dotted non-negative integers (`/^\d+(?:\.\d+)*$/`), defaulting missing `version` to `"0.1"` in `tenet fix`. First blessing keeps the document's existing `version`; re-blessing when any section's blessed text changes increments the final integer component (`"0.1"` -> `"0.2"`). If a hand-authored legacy document has a non-numeric `version` (for example `"v1"`), re-blessing increments a trailing `.<digits>` suffix if present or else appends `".1"` rather than failing with `TN-SCHEMA`.

2. **Log granularity and unavailable measures (`contracts.md` §1; `onboarding.md` §§1, 3 `ALG-13`)**
   `<records>/blessed/log.jsonl` records one JSON object per finished section action: `{doc, section, action, by, at, minutes, statements, session_id?}`, where `action` is `"bless" | "confirm" | "reject" | "defer"`, `minutes` is cumulative elapsed session minutes at write time, and `session_id` is an optional session correlator. When `drafted_at_rev` is absent or the section text at that commit cannot be read, every field in `statements` (`drafted`, `kept`, `edited`, `adopted`, `added`) is `null`. Adoptions (`origin: inferred` -> `asked`) with unchanged normalized text count in both `kept` and `adopted`; deleted drafted statements count in `edited` (`kept + edited === drafted`). A `defer` action still writes a snapshot row (`statements` computed or `null`), while `ALG-13` scoring excludes `action === "defer"` rows from the denominator.

3. **Contradiction review and owner eligibility (`algorithms.md` `ALG-03`; `onboarding.md` §1)**
   Conflict items apply to their named `section` slug or heading (or document-wide when `null`) and may carry optional `(affects: ID1, ID2)`. When open conflicts exist on a section, `bless` presents each one, asks which drafted statement ID it contradicts (or `no`), opens the editor for that statement, verifies that the chosen statement's normalized text changed or was removed before writing `resolution:` (accepting `Resolution:` case-insensitively on read), or exits with `TN-BLESS-OPEN-CONFLICT` if postponed. In `alpha.0` (`recorded: "self"`), the owner picker offers configured `owners[].id` values (falling back to `ownersFor` when none are listed) without restricting choices to section owners; section/CODEOWNERS authorization belongs to `alpha.1` forge review.

4. **Anchor sidecar format and copy naming (`algorithms.md` `ALG-03`)**
   Blessed copies live at `<records>/blessed/<doc path with / as __>/<slug>.md` (always retaining `.md`), resolved under `<records>/blessed/` via `confine`, rejecting `/` vs `__` path collisions with `TN-SCHEMA`, and preserving host filename case with UTF-8 LF normalization. `<blessed_copy>.anchors.json` is a JSON object `{ "<exact citation key>": "<normalized cited lines joined by \\n>" }` matching `anchorsFor` (CRLF -> LF, trailing `[ \t]` trimmed per line). During `confirm`, if a cited target file is missing or unreadable, `bless` displays `(unavailable)` and refuses re-anchoring (`TN-CITE-FILE`), leaving the prior blessed copy in force.

5. **Card wording and PR handoff (`onboarding.md` §1)**
   Reference goldens in `pkg/conformance/cards/` follow `onboarding.md` §1 literally: omit the conflicts block when zero conflicts remain, compute per-section reading time as `Math.ceil(words / 200)` using singular `minute` for `1` and `minutes` otherwise (`"Sections (about <n> minutes)"`), and emit literal `<n>` when `--pr` is omitted. In `draft-specs`, agents commit drafted spec changes first, then run `tenet onboard --card` (which stamps `drafted_at_rev` cleanly without tripping `TN-SUBJ-DIRTY`), commit the stamped header, and open the PR. Existing `drafted_at_rev` stamps remain pinned across reruns and rebases/squashes unless explicitly cleared or re-baselined (`--refresh`).

6. **Recovery from termination or concurrent writes (`algorithms.md` `ALG-03`; `onboarding.md` §1)**
   Each finished section immediately persists its blessed copy, updates `<blessed_copy>.anchors.json`, updates the spec file via `writeAtomic`, and appends its `log.jsonl` row; any write failure rolls back that single action's modified files. `EOF` or `SIGINT` stops cleanly after the last finished section, preserving completed sections. Before writing the spec file, `bless` re-verifies that the file on disk matches the session's pre-edit/parsed digest and fails with `TN-SUBJ-DIRTY` if concurrently modified. Cross-process lockfiles and multi-file crash journals stay out of scope for `alpha.0`.
