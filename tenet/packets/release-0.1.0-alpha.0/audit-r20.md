## Package and CI evidence

- `npm ci` and `npm pack` from a clean candidate worktree exited 0. The tarball was `vedprakash-m-tenet-0.1.0-alpha.0.tgz`, 1,133,009 compressed bytes and 6.6 MB unpacked as reported by npm. SHA-256 was `d04d2b98bf2f330e1ee89c1208b16680b4c08dab8f4088a6e3efd3560a83e119`.
- Archive layout was three root files (`LICENSE`, `README.md`, `package.json`), 243 `dist/` files, 53 `kit/` files and 625 files across the 13 allowlisted alpha.0 conformance suites. The CLI, SDK, kit changelog and all four install-command result schemas were present. No `tenet/`, `test/`, `pkg/evals/`, `src/`, `runner/`, `.github/`, `package-lock.json` or `LICENSE-docs` shipped. The packed README points to source-only files using relative links, including the experience spec, contributor instructions and documentation license. Those targets are absent in an unpacked install.
- The exact README `npm install --global ./vedprakash-m-tenet-0.1.0-alpha.0.tgz` exited 1 with `ERR_SSL_SSL/TLS_ALERT_HANDSHAKE_FAILURE` on `ajv`. The UX Part 0 registry command `npm install --global @vedprakash-m/tenet@0.1.0-alpha.0` failed with the same TLS error at the package endpoint. That error leaves registry availability unverified from this machine. For the Windows walkthroughs, npm installed the original tarball both globally and into a fresh scratch project using a loopback mirror of dependency bytes verified by the release lockfile. Both installs exited 0. The PowerShell `tenet.ps1` found on PATH and project `node_modules\.bin\tenet.cmd` printed `0.1.0-alpha.0`. Help returned 0 and listed all four install and maintenance commands. The mirror establishes a real npm installation and shim launch with pinned dependencies. Repeat the ordinary public-registry path on a network that can reach it.
- **Release blocker for both journeys.** The installed candidate's `tenet init` wrote `x-integrity-source: local` and an integrity value different from the actual tarball's SHA-512 in both repositories. On the empty-project copy, `tenet upgrade --json` returned success from alpha.0 to alpha.0, repeated the local-integrity warning, and kept the lock's same digest. [The integrity resolver](../../../src/install/integrity.ts) skips registry lookup for any version containing a hyphen, which includes a published alpha.0. [The generated CI workflow](../../../kit/workflows/tenet.yml) hashes the npm tarball and rejects a difference. Publishing the same bytes alone leaves this path broken. CP-0010 and CP-0051 owners should prove a registry-pinned alpha upgrade and the generated test and recorder workflows against that exact artifact.
- **Hosted main CI.** `gh run list --branch main` and `gh run view <id> --json status,conclusion,jobs` showed macOS, Ubuntu and Windows all green at [candidate run 45501731238](https://github.com/vedprakash-m/tenet/actions/runs/45501731238). The immediately preceding run for `67d8781` was cancelled. All three jobs also passed on [the preceding completed successful run for `9f0b0a4`](https://github.com/vedprakash-m/tenet/actions/runs/45499903502). The normal matrix runs the packed-bin smoke test. The release workflow's downloaded-artifact job also calls that same smoke test, whose scope is version, help, inventory, check, board and SDK. Neither provides real UX 1A and 1B endpoint evidence. Extend release proving to retain that evidence.
