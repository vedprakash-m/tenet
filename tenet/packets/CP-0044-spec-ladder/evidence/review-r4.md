## Blockers

- **B1 · Git-backed proving fails under Windows CRLF settings.** `test/specs/conformance.test.ts:191–194,213–226,562–580,593–615` versus `alpha.0.md:122`. The temporary repositories inherit the machine's Git conversion settings. Git aborted on `LF would be replaced by CRLF`, so none of the 13 ALG-14 or two other Git-backed assertions ran. Node counts the failed suite as the sixteenth failure. **Fix:** configure LF-preserving Git in the fixture repositories or reuse the existing temp-repository helper before staging, and retain the exact comparisons.
- **B2 · Fenced examples become live specification items.** `src/specs/parse.ts:426–491,528–545,571–575` versus `algorithms.md:20` and `contracts.md:57–63`. The section pass protects fences but the statement pass processes all body lines as Markdown lists and tables. A fenced `- R-9 Example only.` is returned alongside the real `R-1`. It can introduce a duplicate or reach downstream evidence. **Fix:** preserve fence bytes in section text and digest while excluding them from statement parsing.
- **B3 · Metadata outside braces is accepted when another metadata block exists.** `src/specs/parse.ts:142–163` versus `contracts.md:63`. `- R-1 Keep it. origin: asked {serves: V-1}` is accepted with `origin: null` and the metadata token embedded in text. The outside-brace check runs only if no braces are present. **Fix:** reject metadata markers in the text portion even when a valid trailing metadata block is present, and retain the item line and canonical finding.
- **B4 · Malformed citations bypass syntax-first classification and wording.** `src/specs/anchors.ts:24–44` and `src/specs/citations.ts:19–23,59–69` versus `algorithms.md:65–70`, `answers-r2.md:19–22`, and `messages.md:27`. `doc: guide.md#bad slug:5` falls into the path grammar and emits `TN-CITE-FILE`. `src/a.ts:one-two` gets the right code with the generic range message instead of the binding literal `citation is malformed`. **Fix:** dispatch reserved prefixes before validating the whole citation, report one syntax finding with the binding message, and retain the canonical range message for a syntactically valid out-of-bounds range.
- **B5 · Non-test helpers truncate test anchors.** `src/specs/anchors.ts:71–78,93–113` versus `alpha.0.md:114` and `algorithms.md:38`. A peer-indented `def helper():` ends the anchor even though the next qualifying declaration is `def test_next():`. The probe loses the helper and its body from the anchored block. **Fix:** use only the declared test grammar and `describe(` for terminators, retaining the indentation and EOF rules.
- **B6 · A newly added blessed requirement can disappear from touched output.** `src/specs/touched.ts:303–320,324–339` versus `algorithms.md:202,205`. A head-only blessed `R-12` added on a changed line with no citations and no Implements entry never receives `text-changed`, because that reason requires a base item. **Fix:** evaluate the head-side line overlap for head-only blessed candidates independently of base comparisons.
- **B7 · Output loses the specified order between reasons.** `src/specs/touched.ts:324–355` versus `algorithms.md:202–206` and `answers-r2.md:27–29`. A mixed probe returns `R-2/cited-code-changed` before `R-9/implements`. The final global ID sort discards the reason order. **Fix:** sort by reason priority, then numeric ID and ASCII full ID within the reason.
- **B8 · A cited path with spaces misses an overlapping hunk.** `src/specs/touched.ts:104–119,177–183` versus `algorithms.md:204` and `contracts.md:63`. Replacing line 1 of `src/example with space.ts`, cited at line 1, returns `same-area`. The parser retains Git's patch-header path delimiter in the path it compares. **Fix:** decode patch-header paths to Git paths, including separator tabs and quoted paths, before comparing ranges.
- **B9 · Cross-document duplicate IDs are silent.** `src/specs/parse.ts:404–424,571–576`, `src/specs/ladder.ts:52–72` and `src/specs/touched.ts:147–153` versus `alpha.0.md:116` and `contracts.md:63`. A duplicate `R-2` across two ladder documents produces no `TN-SPEC-DUP-ID`, and touched silently keeps the first record. The test at `test/specs/conformance.test.ts:365–384` only exercises duplicates within one file. **Fix:** detect project-level duplicates at the multi-document boundary, emit the specified finding, and test two committed documents.
- **B10 · Deltas drop other parts with the same document kind.** `src/specs/deltas.ts:24–30,86–95` versus `alpha.0.md:112` and `contracts.md:35–40`. With two files declaring `tenet.doc: prd`, editing `R-7` in the second file returns an empty delta. Each side uses only the first matching file. **Fix:** compare items from all documents/parts represented by a document name, preserving rename handling and reporting collisions instead of silently dropping a part.
- **B11 · A citation to a section that never existed is reported as changed.** `src/specs/touched.ts:189–200` versus `algorithms.md:204`. A blessed requirement cites `docs/guide.md#never`. The file is identical at both revisions and the only changed file is unrelated, but the requirement is labeled `cited-code-changed`. **Fix:** distinguish a section absent at both revisions from an existing base section that was deleted or renamed. Leave invalid-citation reporting to ALG-04.

## Shoulds

- **S1 · Document anchor text keeps trailing whitespace.** `src/specs/anchors.ts:8–12,145–152` versus `alpha.0.md:106,114` and `algorithms.md:38`. A doc anchor's hash is normalized, but its stored text retains spaces and tabs at line ends. **Fix:** use the specified line-normalized section body for the doc anchor text and add a whitespace case.
- **S2 · Special-section recognition and resolution lose information.** `src/specs/parse.ts:376–391,440–455` versus `contracts.md:65–72`. `## Conflicts!` is treated as the exact `Conflicts` section. On an actual conflict line, `| resolution: two` after alternatives is stripped before the resolution can be read. **Fix:** recognize the exact headings and extract resolution/answer before stripping option text, with tests for a look-alike heading and a resolved conflict.
- **S3 · Table placeholder semantics leak into braced scope.** `src/specs/parse.ts:103–107,170–174` versus `contracts.md:63` and `onboarding.md:51`. `{scope: -}` becomes `null` even though the braced scope rule allows any non-empty string. The dash placeholders belong to table cells. **Fix:** apply placeholder conversion only at the table boundary.
