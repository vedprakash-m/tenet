# E-0001 · Pack and agent-card shapes are missing

## What was attempted

The 12 records whose shapes appear in C §§1–6, §8 and §10, CI §2 or TS
§6.1 were implemented. Their examples, edge cases and focused tests pass.
No field set was invented for `pack` or `agent-card`.

## Evidence

The focused suite has two skipped tests:

- `pending: kit/schemas/agent-card.json`
- `pending: kit/schemas/pack.json`

## Where it rubs

The CP-0004 contract requires both schemas:

> `kit/schemas/` (new: `tenet-yaml` ... `pack`, `agent-card`, ...).

The named Needs provide no pack record shape. TS §6.1 says only:

> `pack` ... `minimal` ... Lifecycle pack or a path to one.

The pack's actual fields are not stated in TS §6.1, while the sentence that
discusses pack authoring is in excluded TS §6.2.

The named Needs contain no `agent-card` record definition at all; C says that
each format has a schema, but supplies no object notation or field list for
an agent card.

## Hypotheses

- L3: the two shapes are defined in a required source omitted from CP-0004's
  Needs.
- L2: the pack and agent-card contracts still need to be written explicitly.

## What would unblock it

Add the authoritative object shapes to the named Needs, or revise CP-0004 to
name the specification sections containing them. At minimum, provide the
required and nullable fields, field types, enum values and examples for both
records.
