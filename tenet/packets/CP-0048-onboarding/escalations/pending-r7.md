# CP-0048 · Round 7 specification questions

All 13 independent ALG-11 expectations pass. The suite remains unchanged.

1. **Working inputs and deterministic findings.** Contracts §4 (contracts.md:76), OB §1 (onboarding.md:27), and the packet (alpha.0b.md:58) describe the inventory outside observations as a function of HEAD. OB §1 (onboarding.md:14) makes working-tree policy an input, and binding answer 3 lets local reports suppress the no-test-report finding. Case p07 demonstrates the latter. Keep the binding behavior and specify a determinism boundary of HEAD, working policy, and report bytes. Explicitly say that report content lives in observations and report availability can affect findings. Specify what happens when a report is itself tracked.
2. **Refresh scope and draft anchors.** OB §1 (onboarding.md:35, 48, 68–71) and alpha.0b.md:59 require per-unit refresh. The front matter has document-level drafted_at_rev and no unit mapping. The implementation unions the changes since the committed draft anchors, excludes the specification outputs, and treats source changes outside the unit paths as shared. Where there are no anchors, it assigns the current inventory units. Define per-unit source membership and anchors, and behavior for deleted areas, overlapping ownership, shallow history, and missing anchors. Add exact tests for unchanged, shared, deleted, and replaced sources.
3. **Check integration on refresh.** The injected check receives the repository root. Its diagnostics are returned through the CLI envelope and do not enter inventory.findings. Alpha.0b.md:53, 59 does not say if check errors should prevent the assignment write. Define which errors are advisory or fatal, and the required ordering of checks and writes. Wire CP-0009 separately once present.
4. **Classification and extraction tie-breakers.** Onboarding.md:15–25, 29–33 and algorithms.md:176 omit exact language and runner names, recognized manifest and runner lists, project-kind precedence when several signatures coexist, heading/date fallbacks, and CODEOWNERS wildcard areas and colliding IDs. Add a normative table and golden cases. For short doc paths, use document-relative resolution first and repository-relative fallback, while explicitly relative paths resolve only against the document.
5. **Test declaration representation.** Onboarding.md:23 says to take test names from declaration patterns. Contracts.md:76 and the exact cases provide only a numeric cases field. The inventory stores the declaration count from scanTests, and the first findings use its skip matches. Specify whether declaration names belong in a versioned inventory extension or only in later drafting context.
6. **Preflight and managed output paths.** Alpha.0b.md:55 points to the UX Part 1 preflight, whose exact transcript shows init. OB §1 (onboarding.md:9–14) supplies onboard's required information without a fixed transcript. Add an onboard transcript covering dirty source, inventory-only, and refresh. Define whether onboard must reject tracked output locations or leave ignore and ownership guarantees to init.
