# CP-0048 · Round 4 fixture questions

The independent conformance suite in `pkg/conformance/alg-11/` tests the agreed rules of `ALG-11` (`tenet/specs/tech-spec/algorithms.md:174–176`), `OB §1` (`tenet/specs/tech-spec/onboarding.md:9–45`), `contracts §4` (`tenet/specs/tech-spec/contracts.md:62–72`), and `CP-0048` (`tenet/specs/plan/alpha.0b.md:49–63`). The following output details are not pinned by the specification and are left unconstrained in `expected.json` until decided:

1. **`sources.skipped[].reason` vocabulary (`contracts.md:69`, `onboarding.md:15`).** `inventory.json` requires a non-empty `reason` string on every entry in `sources.skipped`, and `OB §1` names seven skip categories (`.env*`, credential files, vendored paths, generated paths, binaries, files over 1 MB, and `onboard.exclude`). What exact `reason` tokens should `onboard` emit for each category, and are `vendor/`, `node_modules/`, `dist/`, `build/`, and generated files listed in `sources.skipped` or only excluded from `size.source_lines`?
2. **Drafting unit IDs, `views`, and merge neighbor tie-breaker (`algorithms.md:176`, `contracts.md:69`).** When `layout` is `"separate"`, `ALG-11` creates one unit per CODEOWNERS area (else one per top-level source folder) and merges any unit under `2,000` source lines into its neighbor. When a small unit sits between two neighbors (as in `p04-merge-small-unit-into-neighbor`), does it merge into the preceding neighbor, the following neighbor, or the smaller/larger neighbor in lexicographic order? What is the canonical `id`, `paths`, and `views` array on each `units[]` entry in `one-file` versus `separate` layout?
3. **`findings[]` message text and `no-test-report` path (`onboarding.md:20–26`, `contracts.md:69`).** `inventory.json` requires `{kind, path, message}` for each entry in `findings[]`. What exact `message` template is expected for each of the four `kind` values (`dead-path`, `skipped-tests`, `owners-unmatched`, `no-test-report`), and what `path` value is used for `no-test-report` when no CI workflow or test report exists (`"tenet.yaml"`, the workflow path, or `"."`)?
4. **Return shape of `onboard({inventoryOnly, refresh, layout})` (`alpha.0b.md:54–59`).** The `CP-0048` contract exports `onboard({inventoryOnly, refresh, layout}) → {preflight, inventory, findings, assignment}`. What are the exact fields of `preflight`, and does top-level `findings` duplicate `inventory.findings` or carry `check` diagnostics when `--refresh` runs against existing drafts?
