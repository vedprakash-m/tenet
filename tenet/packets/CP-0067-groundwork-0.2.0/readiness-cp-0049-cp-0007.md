### Inventions

1. **Exact wire rules for omitted and nested fields** · `tech-spec.md#3-the-seven-primitives` · Use the required keys in TS §3. On fixed-shape objects, reject unknown keys except `^x-`. A subject kind is a nonempty name, including pack kinds. Its `digest` and optional `base` are full algorithm-tagged hashes. Actor roles and chain elements are ID strings. Actor keys have `public_key` and `added` with an optional revocation time. Claim selectors take string IDs and lists of strings for paths and areas. Accept `binary`, `{rule, tolerance}` with finite tolerance, or `{rate, runs}` with rate in [0,1] and positive integer runs. A supplied evidence producer requires `source: ci|local` and may include `verifier_version`, `policy_revision` and `workflow_run`. Inputs can include `runner_image`, `lockfile` and `check_definition` digests. A supplied run identity has string `run` and positive integer `attempt`. A decision references an actor and target by ID. Its proof has string `strength` and `via` and a tagged `policy_revision`. Optional scope is target data. Event `prev` contains event IDs and supplied `data` is a JSON object, with per-event replay admissibility in CP-0007. Step outputs and evidence references are lists of strings and proposed events are event records. Treat omitted optional facts as unknown and keep schema defaults separate from eligibility (`tenet/specs/tech-spec.md:80–98`, `tenet/specs/tech-spec/agents.md:161`, `pkg/conformance/kernel-schemas/p05-fix-loop-assignment-result-criteria/input.json:48–85`).
2. **How schemas and migrations reach callers** · `plan/alpha.1.md#cp-0049` · Add the names to the schema API and generated types. Register schema IDs needed by cross-schema references before compiling validators. Publish the migration module under `pkg/migrations/` with its runtime entry point and preserve `assignment.json`, `packet.json` and `tenet-yaml.json` (`src/core/schema.ts:25,54–68,142`, `package.json:23–39`).
3. **Lossless legacy state alongside the new identity model** · `tech-spec.md#3-the-seven-primitives` and `plan/alpha.1.md#cp-0049` · Proposed for D-1: give a migrated v1 work record its original CP ID and the R10 fields with their observed legacy values. Add a read-only `x-legacy-packet` snapshot of the parsed original, including `stage`, `status`, `endpoint` and extensions. Store the original row in event data as `x-legacy-entry`. Allow legacy-only forms under explicit legacy import rules. Show snapshot facts separately from replayed state and keep authority tied to eligible events. New work identities follow TS §3 (`tenet/specs/tech-spec.md:88`, `tenet/packets/CP-0049-kernel-schemas/escalations/answers-r10.md:13–18`).
4. **Malformed input and deterministic partial results** · `plan/alpha.1.md#cp-0049` · Proposed signature `migratePacket(old: unknown) → {work: WorkV1 | null, events: EventV1[], problems: Finding[]}`. Report an invalid identity, missing `history` or invalid creation with `work: null` and no events, while collecting the known validation findings. For an invalid later row, emit one finding per invalid field in JSON Pointer order, skip that row and link the next emitted event to the last valid event. Use the original zero-based row index even when skipping. Include the field path in registered finding text (`kit/schemas/finding.json:40–56`, `pkg/conformance/kernel-schemas/n06-migrate-malformed-legacy-packet/expected.json:2–19`).
5. **Imported ID domain and bytes** · `contracts.md#1-files-and-identifiers` · For each migration row parse its UTC timestamp into an unsigned 48-bit Unix epoch millisecond value. Parse `YYYY-MM-DDTHH:MMZ` by supplying seconds only for the timestamp and emitted event time. Hash UTF-8 RFC 8785 of exactly `{work: old.id, index, entry: originalParsedHistoryRow}`, with zero-based `index` and the original string in `entry.at`. Take the first ten digest bytes in network order and append their 80 bits to the timestamp's 48 bits. Encode uppercase Crockford Base32 as ten timestamp characters with two zero padding bits on the left, then sixteen suffix characters. Use ancestry to order imported events that share a timestamp. Apply monotonic ID generation to live events. Reject invalid calendar values and noncanonicalizable rows through `TN-SCHEMA` (`tenet/packets/CP-0049-kernel-schemas/escalations/answers-r10.md:17–18`, `src/core/hash.ts:48–107`).
6. **Structural review location and conditional payloads** · `evidence.md#1-evidence-payloads` · When `kind` and `payload` exist, validate the payload variant from evidence §1. Use review status `complete|incomplete`, a positive integer round and boolean `requires_human`. The `findings` and `invalid` arrays contain objects with a nonempty `id` and `origin: introduced|exposed|inherited|uncertain`. A located finding supplies `location` as a forward-slash repo-relative `path:line` or `path:start-end`, plus optional boolean `substantiated`. Require location on each retained finding in a complete review. Put unlocated findings in `invalid`, which requires `status: incomplete`. `resolved` is a list of finding IDs. A minimal evidence record can omit the payload and provides no payload claim. Acceptance of the reserved kinds validates data structure; the evaluator still checks method eligibility (`tenet/specs/tech-spec/evidence.md:25–28`, `tenet/packets/CP-0049-kernel-schemas/escalations/answers-r10.md:20–21`, `pkg/conformance/kernel-schemas/n04-incomplete-review-payload/input.json:17–30`).
7. **One loop cap and its application point** · `agents.md#5-loops` · Resolve D-2. Suggested text: `limits.steps` is a positive integer and may be omitted. The loop consumer uses 20 when it is absent. Schema validation leaves the document unchanged. Require `advance`, `refuse` and `human-gate` in `route.on`. Validate the discriminated step shapes in the schema and keep route targets, counter monotonicity, backward fix references and human option order in `check --pack` (`tenet/specs/tech-spec/agents.md:142–165`, `src/core/schema.ts:54–69`).

### Inventions

1. **Subject type and boundaries** · `tech-spec.md#3-the-seven-primitives` and `algorithms.md#alg-01` · Proposed for D-4: a `git-tree` subject has `kind: "git-tree"` and the `sha256:` digest of ALG-01. The exclusions input supplies the configured records directory and generated-view paths. Match each excluded path exactly or under its slash-delimited descendants, along with `.tenet`. The subject function reads a revision without accessing the working copy. A caller requesting a subject for uncommitted work returns `TN-SUBJ-DIRTY` with no subject. Include symlinks, submodule entries and LFS pointers as listed. Feed original sorted bytes to the hash helper through its byte input (`tenet/specs/tech-spec.md:80`, `tenet/specs/tech-spec/algorithms.md:30–36`, `src/core/hash.ts:9–12`).
2. **Committed streams and path-safe batches** · `tech-spec.md#5-events-reduction-and-replay` · Pin the selected project commit or records commit once. Resolve a packet alias to its packet directory at that revision and select its `events/*.json`, or select `works/pr-<n>/events/*.json` from the pinned records revision for a quick change. Use the project-wide monthly streams for project events. Batch the selected blobs in that snapshot with NUL-framed requests or listed object IDs. Use original path bytes and repo-relative paths and reject paths escaping the pinned tree. Project worktree reads are an explicit advisory input. Return the pinned revision, valid decoded events and structured findings when committed paths or event payloads cannot be read (`tenet/specs/tech-spec.md:88,129,141`, `tenet/specs/tech-spec/ci.md:163–169`, `src/core/git.ts:47–89`).
3. **A stable representation of reduced facts** · `kernel.md#1-state-reduction-and-replay` · `state` is the effective work record or null without an unambiguous creation. `justified_station` is the last legally reached non-tentative station or null. Return `tentative_moves` as `{event_id, station, time, deadline, status}` rows ordered by event ID. Return sorted active conflict head IDs, applied IDs in replay order, held IDs in ASCII order and findings sorted by code then event ID. Use typed `finding.json` findings and D-3 for orphan severity. Treat `decision.made` with `kind: resolve` as the resolving event. Require every active head in `prev`, an active `keep` ID and authority from the recorded snapshot. ## Owner decisions

D-1 · **CP-0049. How do we represent current packet facts that the new identity and history cannot express?** Options are to preserve a compatibility snapshot alongside migrated events, or repair the source records and authorize explicit history amendments before requiring a clean conversion. Recommend the snapshot and no synthetic events. CP-0066 and CP-0067 use values the old schema refuses, and CP-0039 and CP-0058 have snapshots ahead of their recorded station. Keeping the original observations preserves those records without granting extra authority.

D-2 · **CP-0049. Is the default loop step cap 20 or 40?** Options are to align agents §5 with CP-0049 and R10 at 20, or amend CP-0049 and R10 to use 40. Recommend 20. It matches the packet contract and the settled CP-0049 answer, and permits an explicit higher cap wherever the Owner wants one.

D-3 · **CP-0007. Does an orphan fail `check` or warn while holding the event?** Options are to make it structural everywhere, keep the registered warning everywhere, or distinguish a partial snapshot's warning from a proven missing predecessor in a complete store. Recommend keeping the registered warning with a transitive hold. A delayed parent already prevents advancement without failing every partial read. Align the R10 severity and add a check assertion for the chosen outcome.

D-4 · **CP-0007. Which digest is the wire identity for a git-tree subject?** Options are the ALG-01 filtered SHA-256, or the native Git tree OID with a different algorithm and exclusion contract. Recommend the ALG-01 hash. It matches the independent digest and the promised invariance to records and generated views. Amend TS §3's provisional wording.

D-5 · **CP-0007. What lifecycle state can a native forge observation move?** Options are to set fixed ready/draft station targets, use legal destinations defined by the selected pack, or retain the observations without applying station changes until an explicit transition exists. Recommend pack-defined legal destinations with advisory-only fallback, plus a sandbox proof of the target-side trigger and trusted token. Decide how the first observation establishes the work stream before it can move or close. The current recorder and L-0030 do not supply those rules, and the schema and readiness cases must agree on them.
