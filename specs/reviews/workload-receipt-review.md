## Verified (no finding)

- `Obligation.kind` allows `"workload"` (`core/schemas.ts:99`); nothing creates or judges one. `fitness-trend-degraded` is registered at `core/reasons.ts:26` and produced nowhere. Tech Spec Appendix C row exists (line 2298).
- `judgeObligation` requires a fresh passing receipt for every obligation in the list (`core/verdict.ts:53-69`), so adding `OB-workload` to every contract would block every contract; lane-dependent derivation is correct. `category` is not read by the verdict (it is read once, for `acceptance`, in `decisions/basis.ts:124`).
- `receiptsOf` sends every non-static obligation to the shared Vitest report (`verbs/check-evidence.ts:101`); the e2e route (`isE2e`, `withE2e`, `runE2e`) is the precedent.
- The golden fixture prints one JSON report with `mode`, `referencePass`, `reasons`, `protocol.minimumSamples`, `environment`, `qualification: "unqualified"`; the neutral starter has no `workload/`, no `workload.json` and no `workload` key in `recipe.json`.
- Appendix text arithmetic: 2,760 / 37 = 75 and 4,320 / 37 = 117 are correct for the stated base. `e2e` function sizes were not re-measured.
- `AttentionItem` has `id`, `path`, `line`, `pattern`, `marker`, optional `disposition` (`core/schemas.ts:147`); `carryDispositions` and `attentionOf` exist (`core/review.ts:38`, `verbs/check-evidence.ts:218`).
