# SP-11 feasibility, run HC-01 (2026-10-24)

Authorized by the owner for exactly one live run: Copilot CLI, the owner's account, `TENET_HOST_RUNS=1`, 5-minute timeout, default model. No further run is authorized.

**Tuple.** GitHub Copilot CLI 1.0.104-3 · model `gpt-6.1-sol`, forced by an administrator-managed setting (the default model could not be chosen) · Node 26.3.0 · Git 2.56.0 · darwin 27.0.0 arm64. Not VS Code desktop.

**Result.** The run finished (exit 0, 30.8 s, 1 premium request, 277 KB transcript) but did **not** reach the kernel: `.tenet/state` was not created, so HC-01 failed on its own evidence rule. The model's final message said so honestly.

**Observed (from the transcript's event stream).**
- `--plugin-dir` works headlessly: the `tenet` skill loaded from the plugin (version 0.1.0-m0) and the coordinator dispatched `tenet:tenet` as a subagent.
- The host reports the subagent's declared tool list (`edit, read, search, execute, todos, vscode/askQuestions, agent`). That is a host report of declaration, not proof of enforcement.
- The subagent tried to find the skill by a shell command and a glob over `/Users`, `/tmp` and the OS temp folder. Both were denied: "Permission denied because no interactive user response was available". `--allow-all-tools` and `--add-dir <plugin>` did not cover them. The prompt gave the subagent no kernel path.
- The user's other plugins and MCP servers (one of which failed to spawn) loaded into the run, so a run is not isolated from the owner's configuration.
- The result event carries `premiumRequests` and durations, so cost per run is machine-readable.

**Not observed.** Any kernel call from the host; tool enforcement; context isolation; parallel or cancelled children; VS Code desktop behavior; behavior with an isolated configuration directory.

**Consequences.** (1) Headless runs and cost capture are feasible on the CLI. (2) The next attempt needs the kernel path stated in the prompt or `--allow-all-paths`, and an isolated config directory so the owner's other plugins do not load; that is a second run and needs separate authorization. (3) Whether VS Code chat can be driven unattended is still unanswered.

## Run 2 (2026-10-24, second and last authorized run)

Authorized by the owner: `TENET_HOST_RUNS=2` total, kernel path stated in the prompt, `--allow-all-paths`, an isolated `COPILOT_HOME`, 5 minutes, default model. Same tuple as run 1 (Copilot CLI 1.0.104-3, `gpt-6.1-sol` forced by the administrator setting, Node 26.3.0, Git 2.56.0, darwin arm64).

**Result: HC-01 passed.** Exit 0, 30.3 s, 1 premium request, zero denied calls. The kernel's own `.tenet/state` held a `plan` contract, which is the evidence the test decides on; the model's final message (contract `W1.1.2e7l`, one TODO at `a.ts:1`) agrees with it but was not what the test relied on.

**Observed.**
- An empty `COPILOT_HOME` removed the owner's other plugins: only the built-in GitHub MCP server loaded. Authentication still worked from the system keyring, so no token was read or passed.
- The coordinator loaded the `tenet` skill, dispatched `tenet:tenet` as a subagent, which read `skills/tenet/SKILL.md` and `tenet-intake/SKILL.md`, ran the kernel as `env -u NODE_OPTIONS node <path>/tenet.mjs open plan ...`, and submitted a plan through the kernel. It then stopped at the plan-confirmation consent gate instead of confirming for the user, as the skill requires.
- Compared with run 1: stating the kernel path and adding `--allow-all-paths` removed both denials.

**Not observed.** VS Code desktop; tool enforcement (the tool list is a host-reported declaration); context isolation; parallel, cancelled or dead children; a full open→check→review→finish task; the 15-minute command; behavior under a different model.

**What this establishes.** A headless, repeatable, cost-counted native run of the installed plugin is feasible on the Copilot CLI tuple above, with the verdict taken from kernel state. That answers SP-11's "unattended runs" question for the CLI only. It is one run on one task; it does not qualify anything and is not a disposition of SP-08, SP-01 or SP-02.
